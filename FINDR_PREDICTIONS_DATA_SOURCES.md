# Findr Fish Recommendations - Data Sources & Connections

## Overview

The Findr "biting now" recommendations shown on the homepage are generated by **PostgreSQL RPC functions** that combine **live environmental data** with **species-specific preference data** to calculate confidence scores for each species in a given ICES rectangle.

---

## RPC Functions

### 1. `get_environmental_predictions_basic()`
- **Purpose**: Generate predictions without GPS data
- **Location**: `/supabase/migrations/20251017001_add_bio_to_predictions.sql`
- **Parameters**: 
  - `target_rectangle` (text): ICES rectangle code
  - `target_date` (date): Prediction date

### 2. `get_environmental_predictions_enhanced()`
- **Purpose**: Generate predictions with GPS-enhanced scoring (depth + substrate)
- **Location**: `/supabase/migrations/20251017002_add_bio_to_enhanced_predictions.sql`
- **Parameters**:
  - `target_rectangle` (text): ICES rectangle code
  - `target_date` (date): Prediction date
  - `user_lat` (numeric): User's latitude
  - `user_lon` (numeric): User's longitude
  - `user_substrate` (text): Substrate from EMODnet
  - `user_depth_m` (numeric): Depth from EMODnet

## Data Sources Connected to Species Information

### 🌊 1. Live Environmental Conditions
**Table**: `findr_conditions_snapshots`

**Columns Used**:
```sql
- rectangle_code (text)
- sea_temp_c (numeric)              -- Sea surface temperature
- chlorophyll_mg_m3 (numeric)       -- Chlorophyll concentration (baitfish indicator)
- dissolved_oxygen_mg_l (numeric)   -- Oxygen levels (habitat quality)
- salinity_psu (numeric)            -- Salinity (species preference)
- captured_at (timestamp)           -- When data was captured
- snapshot_date (date)              -- Date of conditions
```

**Data Freshness**:
- Queries last 7 days of data: `target_date - INTERVAL '7 days' AND target_date`
- Handles split snapshots (multiple readings per day)
- Aggregates using MAX() to get most recent values per parameter

**Query Logic** (lines 33-45):
```sql
WITH recent_conditions AS (
  SELECT 
    rectangle_code,
    MAX(CASE WHEN sea_temp_c IS NOT NULL THEN sea_temp_c END) as sea_temp_c,
    MAX(CASE WHEN chlorophyll_mg_m3 IS NOT NULL THEN chlorophyll_mg_m3 END) as chlorophyll_mg_m3,
    MAX(CASE WHEN dissolved_oxygen_mg_l IS NOT NULL THEN dissolved_oxygen_mg_l END) as dissolved_oxygen_mg_l,
    MAX(CASE WHEN salinity_psu IS NOT NULL THEN salinity_psu END) as salinity_psu,
    MAX(captured_at) as latest_capture
  FROM findr_conditions_snapshots
  WHERE rectangle_code = target_rectangle
    AND DATE(captured_at) BETWEEN target_date - INTERVAL '7 days' AND target_date
  GROUP BY rectangle_code
)
```

### 🐟 2. Species Master Table
**Table**: `species`

**Columns Used**:
```sql
- id (uuid)                    -- Species unique identifier
- species_code (varchar(50))   -- Standard species code (e.g., "COD")
- name_en (varchar(100))       -- English common name
- scientific_name (varchar(200)) -- Latin binomial name
- playful_bio_en (text)        -- Fun species description for cards
```

**Join Logic** (lines 47-59):
```sql
biogeochemical_enhancements AS (
  SELECT
    s.id as species_id,
    s.species_code,
    s.name_en,
    s.scientific_name,
    s.playful_bio_en,
    target_rectangle as ices_rectangle,
    target_date as prediction_date,
    rc.sea_temp_c as env_temperature,
    rc.chlorophyll_mg_m3 as env_chlorophyll,
    rc.dissolved_oxygen_mg_l as env_oxygen,
    rc.salinity_psu as env_salinity,
    rc.latest_capture
  FROM species s
  CROSS JOIN recent_conditions rc
  WHERE s.name_en IS NOT NULL
)
```

**Note**: CROSS JOIN creates predictions for **all species** against the environmental conditions.

### 📊 3. Species Bio-Band Preferences
**Table**: `species_bio_bands`

**Schema**:
```sql
- species_id (uuid)          -- Links to species.id
- parameter (text)           -- 'chlorophyll', 'oxygen', 'salinity', 'surface_temperature'
- happy_bands (integer[])    -- Array of band levels where species thrives (scores 10 points)
- unhappy_bands (integer[]) -- Array of band levels species avoids (scores 2 points)
```

**Example Data**:
```
Species: Atlantic Cod
- chlorophyll: happy_bands = [2,3], unhappy_bands = [5,6]
- oxygen: happy_bands = [4,5], unhappy_bands = [1,2]
- salinity: happy_bands = [3,4], unhappy_bands = [1]
- surface_temperature: happy_bands = [2,3], unhappy_bands = [5,6]
```

**Scoring Logic** (lines 61-138):
For each species and each parameter (chlorophyll, oxygen, salinity):
1. Look up current environmental value
2. Find which bio-band level it falls into (using `bio_bands_thresholds`)
3. Check if that level is in species' happy_bands (10 points) or unhappy_bands (2 points)
4. Otherwise, neutral (5 points)

---

### 📏 4. Bio-Band Threshold Definitions
**Table**: `bio_bands_thresholds`

**Schema**:
```sql
- idx (integer)              -- Sort order
- parameter (text)           -- 'chlorophyll', 'oxygen', 'salinity', 'surfaceTemperature'
- level (integer)            -- Band number (1-7, where 1=lowest, 7=highest)
- threshold (numeric)        -- Minimum value for this band
- angler_interpretation (text) -- Human-readable meaning
```

**Example Data**:
```
Chlorophyll (mg/m³):
- Level 1: threshold 0.0   → "Oligotrophic (clear, low nutrients)"
- Level 2: threshold 0.5   → "Low productivity"
- Level 3: threshold 1.0   → "Moderate productivity"
- Level 4: threshold 2.0   → "Good feeding conditions"
- Level 5: threshold 5.0   → "High productivity"
- Level 6: threshold 10.0  → "Very high productivity"
- Level 7: threshold 20.0  → "Eutrophic (very rich)"

Oxygen (mg/L):
- Level 1: threshold 0.0   → "Anoxic (fish kill zone)"
- Level 2: threshold 2.0   → "Hypoxic (stress)"
- Level 3: threshold 4.0   → "Low oxygen"
- Level 4: threshold 6.0   → "Adequate oxygen"
- Level 5: threshold 8.0   → "Good oxygen"
- Level 6: threshold 10.0  → "Excellent oxygen"
- Level 7: threshold 12.0  → "Supersaturated"
```

**Query Pattern** (lines 77-87):
```sql
-- Find which band level the current environment falls into
SELECT level
FROM bio_bands_thresholds
WHERE parameter = 'chlorophyll'
  AND env_chlorophyll >= threshold
ORDER BY threshold DESC
LIMIT 1
```

## Confidence Scoring Algorithm

The RPC calculates a **0-100 confidence score** for each species by combining:

### Score Components (Basic Function)

| Component | Max Points | Data Source |
|-----------|-----------|-------------|
| **Bio-Band Score** | 30 | `species_bio_bands` + `bio_bands_thresholds` + live conditions |
| **Temperature Score** | 25 | `species_bio_bands` (surface_temperature) + live temp |
| **Substrate Score** | 12 | Fixed (basic function has no substrate data) |
| **Freshness Score** | 20 | Age of environmental data |
| **Completeness Score** | 15 | Species data quality (has bio-bands, name, bio, etc.) |
| **TOTAL** | **102** → capped at 100 |

### 1. Bio-Band Score (0-30 points)

Combines **three parameters**: chlorophyll, oxygen, salinity

**Calculation** (lines 140-149):
```sql
LEAST(30, COALESCE(
  COALESCE(bbm.chlorophyll_score, 0) + 
  COALESCE(bbm.oxygen_score, 0) + 
  COALESCE(bbm.salinity_score, 0),
  15  -- Default if no bio-band data
))
```

**Individual Parameter Scoring**:
- **10 points**: Current level in species' happy_bands
- **5 points**: Current level is neutral (not in happy or unhappy)
- **2 points**: Current level in species' unhappy_bands
- **0 points**: No data available

**Example**:
```
Atlantic Cod in rectangle with:
- Chlorophyll = 1.2 mg/m³ → Level 3 → Cod's happy band → 10 points
- Oxygen = 7.5 mg/L → Level 5 → Cod's happy band → 10 points  
- Salinity = 33 psu → Level 3 → Neutral → 5 points
Total bio-band score: 25 points
```

---

### 2. Temperature Score (0-25 points)

Uses species' **surface_temperature** preferences from `species_bio_bands`.

**Logic** (lines 151-170):
```sql
CASE 
  WHEN env_temperature IS NULL THEN 15  -- Default
  WHEN EXISTS (
    -- Check if current temp is in species' happy_bands
    SELECT 1
    FROM species_bio_bands sbb
    JOIN LATERAL (
      SELECT level
      FROM bio_bands_thresholds
      WHERE parameter = 'surfaceTemperature'
        AND env_temperature >= threshold
      ORDER BY threshold DESC
      LIMIT 1
    ) bbt ON true
    WHERE sbb.species_id = species_id
      AND sbb.parameter = 'surface_temperature'
      AND bbt.level = ANY(sbb.happy_bands)
  ) THEN 25  -- Perfect temp!
  WHEN env_temperature >= 8 AND env_temperature <= 18 THEN 20  -- Good range
  WHEN env_temperature >= 5 AND env_temperature <= 22 THEN 15  -- Acceptable
  ELSE 10  -- Outside comfort zone
END
```

---

### 3. Substrate Score (0-20 points)

**Basic Function**: Fixed at 12 points (no substrate data)

**Enhanced Function** (when GPS provided):
```sql
CASE
  -- User substrate matches species' preferred substrates
  WHEN user_substrate IS NOT NULL AND EXISTS (
    SELECT 1 FROM species_substrates ss
    WHERE ss.species_code = species_code
      AND ss.substrate_type = user_substrate
      AND ss.preference_level IN ('preferred', 'tolerated')
  ) THEN 20
  
  -- No substrate data available
  WHEN user_substrate IS NULL THEN 12
  
  -- Substrate data exists but doesn't match species
  ELSE 8
END
```

---

### 4. Freshness Score (0-20 points)

How recent is the environmental data?

**Logic** (lines 180-186):
```sql
CASE
  WHEN DATE(latest_capture) = target_date THEN 20        -- Today!
  WHEN DATE(latest_capture) >= target_date - 1 THEN 18   -- Yesterday
  WHEN DATE(latest_capture) >= target_date - 3 THEN 15   -- 3 days old
  WHEN DATE(latest_capture) >= target_date - 7 THEN 12   -- Within week
  ELSE 8                                                  -- Older data
END
```

---

### 5. Completeness Score (0-15 points)

Data quality metric - how much do we know about this species?

**Logic** (lines 187-192):
```sql
(
  (CASE WHEN EXISTS (SELECT 1 FROM species_bio_bands WHERE species_id = ...) THEN 6 ELSE 0 END) +
  (CASE WHEN EXISTS (SELECT 1 FROM species_substrates WHERE species_code = ...) THEN 4 ELSE 0 END) +
  (CASE WHEN name_en IS NOT NULL THEN 2 ELSE 0 END) +
  (CASE WHEN scientific_name IS NOT NULL THEN 2 ELSE 0 END) +
  (CASE WHEN playful_bio_en IS NOT NULL THEN 1 ELSE 0 END)
)
```

**Breakdown**:
- **6 points**: Has bio-band preferences
- **4 points**: Has substrate preferences  
- **2 points**: Has common name
- **2 points**: Has scientific name
- **1 point**: Has playful bio description

## Data Flow Summary

### Request Flow
```
1. User visits Findr homepage
   ↓
2. Frontend determines ICES rectangle from GPS
   ↓
3. POST /api/findr/predictions
   - rectangleCode: "31F2"
   - predictionDate: "2025-10-17"
   - latitude: 43.5 (optional)
   - longitude: -8.2 (optional)
   ↓
4. API checks cache (3-hour TTL)
   ↓
5. If no cache: Call RPC function
   - get_environmental_predictions_basic (no GPS)
   - get_environmental_predictions_enhanced (with GPS)
   ↓
6. RPC function executes:
   ├─ Query findr_conditions_snapshots (last 7 days)
   ├─ CROSS JOIN all species
   ├─ For each species:
   │  ├─ Match chlorophyll level → Check species_bio_bands → Score
   │  ├─ Match oxygen level → Check species_bio_bands → Score
   │  ├─ Match salinity level → Check species_bio_bands → Score
   │  ├─ Match temperature level → Check species_bio_bands → Score
   │  ├─ Check substrate (if GPS provided)
   │  ├─ Score data freshness
   │  └─ Score data completeness
   ├─ Calculate total confidence (0-100)
   └─ Return species sorted by confidence DESC
   ↓
7. API augments with localized names
   ↓
8. Cache result for 3 hours
   ↓
9. Return JSON to frontend
```

## Key Tables Relationships

```
species (master)
├─ id → species_bio_bands.species_id (1:many)
│  └─ Defines parameter preferences (chlorophyll, oxygen, salinity, temp)
│     └─ References bio_bands_thresholds for level definitions
│
├─ species_code → species_substrates.species_code (1:many)
│  └─ Defines substrate preferences (sand, mud, rock, etc.)
│
└─ Provides display data: name_en, scientific_name, playful_bio_en

findr_conditions_snapshots (live data)
├─ rectangle_code → ICES rectangle
└─ Provides: sea_temp_c, chlorophyll_mg_m3, dissolved_oxygen_mg_l, salinity_psu
   └─ Matched against bio_bands_thresholds to find levels
      └─ Compared to species_bio_bands to determine if happy/unhappy
```

## Example: Atlantic Cod Prediction

**Input**:
- Rectangle: 31F2 (Asturias, Spain)
- Date: 2025-10-17
- Live conditions:
  - Temperature: 15°C
  - Chlorophyll: 1.2 mg/m³
  - Oxygen: 8.5 mg/L
  - Salinity: 34 psu

**Processing**:

1. **Find Bio-Band Levels**:
   - Temp 15°C → Level 3 (8-12°C range)
   - Chlorophyll 1.2 → Level 3 (1.0-2.0 range)
   - Oxygen 8.5 → Level 5 (8-10 range)
   - Salinity 34 → Level 4 (32-35 range)

2. **Check Cod's Preferences** (from `species_bio_bands`):
   - Temperature Level 3 → In happy_bands → **25 points**
   - Chlorophyll Level 3 → In happy_bands → **10 points**
   - Oxygen Level 5 → In happy_bands → **10 points**
   - Salinity Level 4 → Neutral → **5 points**

3. **Other Scores**:
   - Substrate: No GPS → **12 points** (default)
   - Freshness: Data from today → **20 points**
   - Completeness: Has all data → **15 points**

4. **Total Confidence**: 25 + 25 + 12 + 20 + 15 = **97/100** ✅

**Result**: Atlantic Cod appears near top of "biting now" list!

## Summary

**The Findr "biting now" recommendations are generated by matching:**

✅ **Live environmental conditions** (`findr_conditions_snapshots`)  
✅ **Species-specific bio-band preferences** (`species_bio_bands`)  
✅ **Threshold definitions** (`bio_bands_thresholds`)  
✅ **Species master data** (`species`)  
✅ **Substrate preferences** (`species_substrates` - enhanced only)

**Confidence scores (0-100) combine:**
- 30 points: Bio-chemical matching (chlorophyll, oxygen, salinity)
- 25 points: Temperature preferences
- 20 points: Substrate match (if GPS provided)
- 20 points: Data freshness
- 15 points: Data completeness

**Result**: A ranked list of fish species most likely to be biting based on current marine conditions in the user's location! 🎣
